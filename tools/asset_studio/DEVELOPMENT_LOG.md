  Ver 0.1.0 | 立项：素材工坊完整链路跑通（试点 NightElf + 第二章廊桥）
    - 立项动因：TEST 模式休眠后换成存档系统，保留了"任意节点进游戏测试"的能力，
      但失去了一个做素材用的草稿箱 —— 本工具补回这块能力，并与存档系统分工
      （存档管"从任意节点测玩法"，工坊管"做素材"）

    - 核心前提：主游戏的美术素材不是图片文件，而是 C++ 绘制代码
      （仓库 0 张图片、173 处 SDL_RenderDrawLine、0 处加载图片），
      因此工具必须直接调用游戏的真实绘制代码渲染，而不是重新实现一遍，
      否则预览会与游戏实际画面持续漂移。本工具据此确立"渲染真值只有一个"

    - 新增无头渲染器 renderer/assetstudio.cpp：用 SDL 软件渲染器在内存里出图，
      不需要窗口与显示器，可脚本化批量运行

    - 新增颜色拦截层 renderer/color_intercept.h（关键技术）：
      工具自定义 SDL_SetRenderDrawColor 覆盖动态库中的同名符号，
      把游戏请求的颜色过一遍调色板再转交真正的 SDL，
      于是"改阵营配色"不需要动主游戏一个字符（白 255,255,255 → 红 255,60,60 已实测）

    - 新增调色板 renderer/palette.h：己方白 / 敌方红 / 技能绿 / 中立青 / 金 / 紫，
      支持自定义 R,G,B 与 tint 模式（保留亮度、套用色相）

    - 新增中央素材注册表：每个素材登记一条链式配置（id/名称/章节/类型/标签/状态/参数/绘制入口），
      绘制入口用适配 lambda 承担"构造实例 → 摆好状态 → 调用游戏 draw()"，
      因此即使某些类的成员是 private 也能接入

    - 注册表放在工具侧（registry/），靠 -I 指向游戏目录 include 游戏头文件，
      于是主游戏零新增文件、零改动，单向依赖从物理上杜绝工坊弄坏游戏的可能

    - 新增源码扫描器 registry/scanner.py：扫描游戏源码里所有绘制入口，
      与注册表交叉比对，报出"源码里有、注册表里没有"（漏登记）与
      "注册表里有、源码里已消失"（重构后登记腐烂）两类问题

    - 新增极简 PNG 写出 renderer/png_writer.h：用 zlib 直接写 PNG，
      绕开未安装的 SDL2_image，输出环节零第三方依赖

    - 新增文本化检视通道 renderer/inspect.h：字符画 + 像素分析（包围盒/内容像素/
      线宽估计/上下左右镜像对称度/颜色分布）。
      AI 侧读不了图片，这条通道是 vibe coding 闭环可验证的前提；
      字符画降采样用块内最大值而非平均值，否则 1 像素细线会整条消失

    - 新增本地服务 server.py：把渲染器包成 HTTP API，提供按需渲染 + 磁盘缓存 +
      GIF 合成（PIL）+ 源码片段 + 扫描报告 + 草稿读写，零第三方依赖（除 GIF 用 PIL）

    - 新增网页画廊 web/：缩略图墙 / 双轴筛选（章节 × 类型）/ 搜索 / 标签 /
      动画 GIF 与进度拖动 / 参数滑块 / 创作辅助叠加层（网格·坐标轴·对称轴·包围盒）/
      真实场景开关 / 零件树 / 克隆为草稿 / 导出代码 / 查看源码

    - 新增草稿区 drafts/ 与自动发现 drafts/gen_drafts.py：
      往 drafts/ 丢一个目录（draw.h + meta.json），make 时自动生成入口头文件，
      草稿即出现在画廊里；草稿与主游戏完全隔离，改坏也影响不到游戏

    - 新增示范草稿 drafts/nightelf_wide/：把 NightElf 的硬编码尺寸全部参数化，
      打通「克隆 → 调参 → 导出代码」的完整转正流程

    - 素材缩略图自动裁剪到内容包围盒并用最近邻放大：NightElf 在 800×600 画布里
      只有 31×17 像素，不放大根本看不清

    - 实测性能：单次渲染 60~70ms（含进程启动），24 帧动画 170ms，
      缓存命中 0.4ms（约 370 倍加速），GIF 合成 12 帧 800×600 约 340ms

  Ver 0.1.1 | 批量接入全部七类素材 + 批量自检工具
    - 素材从 2 个扩到 45 个，覆盖七大类：
      玩家战机 5（训练机透视/侧滚、暗夜精灵号、德鲁伊号、参数化草稿）、
      普通敌人 3（第一章外星飞船、第二章菱形敌、第二章弹幕敌）、
      Boss 4（TELAMONDO + 血条零件、球体 Boss、MOONWELL WARDEN）、
      子弹弹幕 3（透视子弹含 Boss 光束、侧滚子弹、敌弹）、
      特效技能 7（爆炸、烟花、数字碎裂、冲击波、技能球、脉冲、准星）、
      HUD/UI 14（分数、爱心、双能量条、Boss 条、字库、对话行、4 个 UI 元件、浮动文字）、
      背景场景 11（第一章星空·全屏星空·地面透视·基地·整体、廊桥、门禁 + 3 零件、研究室）

    - 新增 renderer/assetstudio.cpp 的 --verify-all 批量自检：把每个素材的每个状态
      都渲染一遍，检查是否真的画出了东西、声明的场景是否真的叠了上去，
      批量接入必须有它兜底，否则只能靠肉眼赌

    - 自检逻辑改为两遍渲染：第一遍不带场景算素材本体的包围盒，第二遍带场景，
      同时比对两遍画面差异以确认场景真的生效。
      只测一遍会出假阳性——带场景时画布被背景涂满，"非空"就失去意义了

    - 素材参数化的可用性设计：所有素材的"推进帧数"类滑块都按素材的真实生命周期标定，
      例如第一章外星飞船在 1600 帧时才到正常尺寸（31×47），默认值即停在那个位置

    - 注册表按类别拆分为 reg_players / reg_enemies / reg_bosses / reg_fx / reg_hud /
      reg_backgrounds，公共辅助抽到 reg_common.h，asset_registry.h 只做聚合与注册入口

    - 接入要点记录：Ch2SphereBoss 的 bg/state/cells 全在 private 段，
      只能走 init() / startEntering() / startAtCenter() / getState() 这套公有 API，
      其中 startAtCenter() 是游戏为测试模式预留的入口，直接进 FIGHT 态且单元全激活；
      球体入场时 update() 只设置背景滚动速度，实际位移由外部 syncScreenPos() 完成，
      预览里必须自己驱动 scroll，否则球体永远停在屏幕外

    - 接入要点记录：敌人（第一章外星飞船 / 第二章菱形敌 / 弹幕敌）的入场是逐帧动画，
      在屏幕外生成后飞入，所以预览不能只调一次 draw()，必须先推进 update() 若干帧

    - 源码覆盖率从 0 提升到 48/80

    - 顺带发现并记录在 SPEC.md 的游戏源码问题（工具首次把它们量化出来）：
      暗夜精灵号机身填充上下不对称（上半 103 像素 / 下半 62 像素，上下镜像 83.7%，
      草稿里做成开关可直接对比）；第一章外星飞船有约 60% 存活时间只有 4~5 像素
      （地平线以上透视缩放被钳死在 0.17，且下降速度仅 0.08 倍）；
      Warden 进入 DYING 后 draw() 提前返回导致机体瞬间消失只剩爆炸粒子；
      FloatingTextManager::draw() 是空实现（只设色不画像素，真正画字的是
      Game::drawFloatingTexts）；drawTextLine 不自己设置绘制颜色，
      Font::drawChar 依赖调用方先设色，任何调用方漏设那段文字就会隐身

  Ver 0.1.2 | 弹窗遮挡界面修复 + 网页资源缓存策略调整
    - 网页画廊新增 #scan 深链接：http://127.0.0.1:8791/#scan 直接打开"未登记检查"，
      既方便收藏，也让无头浏览器可以端到端验证弹窗（否则按钮点不到就没法自动化测）

    - 新增无头浏览器验证流程：用 Edge --headless=new 抓渲染后的 DOM 与截图，
      再用像素分布分析判读界面。此前只测 API 与脚本逻辑就下结论"功能是通的"，
      漏掉了纯前端 bug —— 教训是接口 200 + 逻辑不抛异常 ≠ 用户能看到东西

    - 新增对话框与旁白框两个素材，自检用例从 73 增至 78 个，全部通过

    - BUGFIX: hidden 属性被作者样式表覆盖，导致画廊从打开起就被"未登记检查"弹窗盖住 ——
      浏览器默认样式表只有 [hidden] { display: none }，而作者样式表里任何 display 声明
      都会无条件覆盖它，工坊的 .detail 类写了 display: flex，于是 #detail 与 #scan-modal
      永远可见，#scan-modal 又因 DOM 靠后画在最上层；
      修复为在 style.css 顶部加 [hidden] { display: none !important; }

    - BUGFIX: 扫描弹窗正文永远空白 —— 扫描按钮被上述弹窗盖住，showScan() 从未执行，
      两个 bug 是同一个根因的两面，随上一条一并解决

    - BUGFIX: 网页资源（html/js/css）原设 Cache-Control: public, max-age=86400，
      改完前端后浏览器最多 24 小时看不到新版、普通刷新也无效 —— 改为 no-store；
      渲染出的图片同样改用 no-store，服务端已有磁盘缓存，代价可忽略但彻底消除看到旧图的可能

    - BUGFIX: showScan() 没有 try/catch，请求失败会永远停在"正在扫描…"且不给任何提示 ——
      补错误提示并指引排查服务是否在运行
